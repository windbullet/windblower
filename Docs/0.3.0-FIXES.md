# 0.3.0：EQ A/B、播放启动、错误诊断和频段删除

这次修改针对真机反馈的四个问题，不更换解码器、SRC 质量或滤波器公式。

## EQ 开关不再触发大幅临时衰减

0.2.0 将总开关也视为一套新参数，先采用 L1 保守上界和额外余量，再整曲/整专辑分析并恢复增益。对于多段或高 Q，这个临时增益可能远低于最终需要的增益，无法用于快速 A/B。

0.3.0 把滤波器配置与 A/B 开关分开。已校准的滤波链在旁路期间继续更新独立状态；开关仅做约 50 ms 的输出过渡，不读取原文件、不发起重新分析、不套用临时保守增益。固定环形缓冲还会带来约 0.17 秒（48 kHz 时）的排队延迟，不把它说成绝对瞬时切换。

默认开启“A/B 保持共同前置增益”，EQ 和旁路沿用同一份静态前置/安全衰减。它避免开关额外改变前置电平，**不是按主观响度进行归一化**，改变频谱仍可能改变听感响度。关闭这个选项后，EQ 关闭会平滑恢复单位增益旁路，链路页明确显示当前状态。

校准同时测量滤波后和相同前置增益的旁路真峰值，采用两者较大的值。否则强衰减 EQ 配正前置时，湿声可能安全而 A/B 干声过载。安全目标仍为 −1 dBTP，只做静态衰减，没有加入动态限幅、软削波或音色处理。

## 本地播放不再等待整曲分析

0.2.0 即使 EQ 关闭也要先完成全曲 8× 测峰；EQ 开启时还可能等待整个连续专辑。MP3 的打开函数另外强制扫描一遍全部帧。

0.3.0 的本地启动先协商真实输出格式，再直接创建解码/输出管线。EQ 已有匹配缓存时直接使用；没有缓存时先以单位增益旁路播放，并明确提示“原音播放中 · EQ 后台校准，完成后生效”。新参数校准时维持当前已生效管线，等完整分析和完整历史恢复后再平滑切入。

因此，不再用未校准的新 EQ 提前播放，也不把临时试听大幅衰减强加给用户。**首次 EQ 准备和大幅调参仍可能需要时间**，长连续专辑、32 段、高采样率会更慢；此次移除的是播放启动的前置等待，不是取消防削波测量。歌曲已播放完或设备发生路由变化时，旧准备任务会取消。

分析缓存按文件顺序/哈希、实际处理采样率、滤波器数值和内核版本索引。总开关和界面频段 UUID 不再影响缓存身份；SQLite 按主键读取单条缓存，避免每次解码所有历史缓存。

MP3 在导入曲库时索引一次并保存准确时长，播放打开使用已有 Xing/LAME 信息、按需建立定位索引，不在首音前强制扫描整文件。无 Xing 的 VBR 文件尤其需要将“导入时准确索引”与“播放时快速打开”区分，不能把快速打开时的估计时长写回曲库。

## 过载与其他错误分开

旧版对解码、网络、状态恢复和真实数字过载统一显示“解码／网络读取异常或数字过载”，无法从那句话确定真机到底出了哪一种问题；工作线程的错误又保存在 thread-local 字符串中，主线程取不到详细内容。

新版给每个播放器保存线程安全的具体错误。真实 PCM 超满刻度会记录峰值 dBFS、曲目索引、样本帧和 EQ 修订号，继续暂停保护；其他错误显示原始原因，保存在“播放链路 → 上次播放错误”。没有删除保护或把过载样本硬裁后继续输出。

参数修改不再将只预热两秒的临时新链送往输出，避免该临时状态与最终完整分析不一致。最终仍重建完整历史。无法仅根据旧的通用提示追溯用户设备的每一次报错，但新版本可以区分并定位实际原因。

## 删除末尾频段不再访问失效索引

旧页面使用数组元素绑定；SwiftUI 在移除末尾行的过程中仍可能读取/写入旧索引，导致越界。新版列表以频段 ID 标识，绑定每次按 ID 查找；已删除的行读取稳定快照、忽略后续写入，不影响其他行。移除当前选择时更新选择；至少保留一个频段。

## 验证内容

- 10 段平直 EQ 反复 A/B，全部 Float32 样本与固定增益参考一致，无临时音量凹陷。
- 10 Hz / Q=30 / +24 dB 滤波链旁路期间保留完整状态，切回后与从头连续处理结果逐样本相同。
- 恢复单位增益旁路后与原解码 PCM 的 Float32 表示一致。
- 强衰减 EQ + 正前置：共享校准保护 EQ 和旁路；测试输出峰值不超过 −1 dBFS。
- 六次经过完整校准的参数修改，不产生过载；真实过载与其他错误分别保留具体文本。
- 原有频响、解码、SRC、定位、完整历史和多音测试继续运行。
- Swift 回归检查：本地旁路启动不提交离线分析；反复开关不增加校准次数且保持共同增益；删除末尾频段后旧绑定继续读写不越界、不复活已删除频段。

上述测试结果与安装包对应构建以 [VALIDATION.md](VALIDATION.md) 的最终记录为准。mini 5 启动耗时、A/B 操作体验与长时间压力表现仍需要真机复测。
