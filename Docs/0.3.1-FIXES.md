# 0.3.1：SRC 超满刻度后的自动恢复

修复本地音乐起播后提示 `PCM overload: +0.0… dBFS`、开关 EQ 和重新打开仍无法播放的问题。

## 原因及复现

用户提供的 24 位 / 96 kHz FLAC 在本机复现了同类报错：

| App 实际输出率 | 起初触发的峰值 | 完整链路 8× 真峰值 | 测得的固定旁路增益 |
| --- | --- | --- | --- |
| 44.1 kHz | +0.040574 dBFS | 1.142755（线性幅度） | −2.159065 dB |
| 48 kHz | +0.049750 dBFS | 1.102729（线性幅度） | −1.849375 dB |

原始整数样本合法，不代表 SRC 后的样本也必然小于满刻度。降采样改变采样时刻和带宽，重建峰值可能超过 ±1。报错显示的是首次遇到的超出样本，不是全曲最大值，不能只放宽约 0.05 dB 的阈值或只削减这个数值。

0.3.0 为缩短起播等待，先播放单位增益旁路、后台准备 EQ；源信号在 EQ 生效前已可能过载。过载后生产线程退出，修改 EQ 或解除暂停不会让该线程重新开始，重启又重复相同的未经校准链路。

## 修复行为

- 本地播放首次检测到超满刻度时停止输出异常样本，自动完整测量不带用户 EQ/前置的解码及 SRC 链路，按 −1 dBTP 目标求出固定衰减，重建播放器并从已播位置继续。
- 源信号安全增益独立于 EQ 开关。关闭 EQ 或取消“A/B 保持共同前置增益”时，仍保留必要的源信号固定衰减；EQ 开启则使用其自身完整校准增益，两者不重复相乘。
- 测量结果按文件哈希/顺序、实际处理采样率和内核版本缓存，在生产线程启动前配置。首次过载时也立即持久化“需要分析”标记；扫描期间退出，重新打开会先补齐分析。
- 已失败的生产线程会被重建，避免重复向已经退出的线程发送 EQ 或恢复播放请求。已做源信号校准后仍然异常会保留错误并暂停，不无止境重试。
- 普通未超满刻度的文件保持原有快速起播方式，不统一降低所有歌曲音量。不放宽过载阈值，不加入硬裁切、软削波或动态限幅器；原文件不变。
- 链路页区分单位增益旁路、共同前置增益和源信号静态防削波，显示源信号衰减及上次错误，并包含在导出诊断中。

首次异常后的完整扫描仍需时间，长连续专辑耗时更长；暂停/停止在准备期间仍有效。保护及缓存针对本地和已完整缓存的文件；即时网络串流需先“缓存后播放”才能完成同样的完整测量。

## 验证

本地用用户样本分别完成 44.1 / 48 kHz 整曲输出，共 `10,995,600` / `11,968,000` 帧；期间提交 EQ 和切换旁路，未再过载。源音频仅用于本机验证，没有上传到公开仓库。

公开回归使用独立生成的 24 位 / 96 kHz 素材：复现无 EQ 的 SRC 超满刻度；应用固定增益后验证整段输出、安全余量、A/B、完整历史恢复及定位。原有频响、解码、SRC、状态与旁路一致性测试继续运行。

原生测试覆盖实际 RemoteIO 上的自动恢复、EQ 开关、控制器重建后的缓存读取，以及扫描尚未完成时保存的恢复标记。最终云端结果、安装包及校验值见 [验证状态](VALIDATION.md)。本机数字验证不等于 mini 5 模拟耳机口实测。
