# EQ 与播放链路复核（0.2.0）

这是 0.2.0 的历史复核。0.3.0 已调整调参、旁路增益及启动行为；当前行为以 [0.3.0 修复说明](0.3.0-FIXES.md) 和 [音频设计](AUDIO.md) 为准，下表中的临时保守试听流程不再由界面使用。

按用户提供的九类检查项目复核实现。结论：Float64 TPT / RBJ 静态 EQ 与按需 SRC 的选择合适；此前的状态重建、曲线显示和输出验证存在不足，本次作了修复。数字链路通过已列出的测试，不代表 mini 5 模拟耳机口已实测，也不代表任意调参动作绝对无瞬态。

## 本次修复的具体问题

1. 高 Q 低频滤波器的衰减历史可能远长于两秒。此前定位直接清状态、停止拖动后仍只预热两秒，不能证明与整首峰值分析一致。现从完整原始序列恢复 SRC/EQ 状态后再使用实测安全增益；临时试听单独标记。
2. 仅变更增益不应丢弃余振。现复制当前状态并按增益比缩放；避免在高 Q 下另起不一致的状态。
3. 连续专辑中途修改 EQ 时，校准也必须包含链路起点至当前曲的历史，不能只分析剩余曲目。现统一起点；原生重建路径列表也随连续解码跨曲更新。
4. 低采样率下此前静默限频、固定频点画图可能漏掉极窄高频陷波。现显示保存值/实际值、动态横轴上限，并包含准确的中心和加密邻域点。
5. 补充极小状态归零；修正合并参数请求时过渡修订号；停止提交已过时的预热链。
6. 过去只读取会话 sampleRate。现先进行不启动播放的 RemoteIO 初始化/回读协商，输出端稳定后才建立 DSP 和分析链路。模拟器曾返回初始化前 0 Hz、初始化后 48 kHz、会话仍为 44.1 kHz，已经验证不能只读初始化前的值。正式初始化及恢复播放时回读客户端与输出端，已报告的有效格式不匹配就停止；初始化后仍无有效输出值时，以会话值配置并明确显示“硬件端未验证”。
7. 只有实际 EQ 与完整连续顺序均和校准记录相符时才直接衔接下一首。中途插曲/改序导致记录不适用时，在曲间重建分析，不沿用失效的安全增益。
8. 扩大内部安全衰减范围，覆盖 32 段高 Q 搁架的极端保守上界；用户前置仍为 −60 至 +24 dB。补充极端组合测试，约 −1889 dB 的临时安全增益可正常建立，不能因超过原内部 −1000 dB 限制而丢弃新配置。

## 本地数字测试结果

Windows / MinGW GCC 16.1；实际编译的 C++ 内核与 FLAC、mpg123、soxr。运行脚本：`verify_dsp.py`、`verify_codecs.py`、`verify_audit.py`。

- 原 140 组频响对照最大误差 `7.60e-8 dB`。
- 新增 168 组边界频响对照（8–192 kHz），最大误差 `9.47e-8 dB`；均小于 `0.01 dB` 门槛。参考也是浮点运算，不将数值写成数学零误差。
- 陷波中心用绝对幅度验证，最大残留 `1.67e-10`；不用零点处无意义的 dB 相对误差。
- 32 个非零峰值/搁架级联与独立参考的最大样本差 `6.01e-16`，测试保留有意义的输出电平。
- 10 Hz / Q=30 / +24 dB 峰值滤波器：原采样率与 48→44.1 kHz 下，定位输出与对应连续片段 Float32 样本一致；连续第二曲定位保留前曲历史。
- 最终校准切换后与完整历史参考 Float32 样本一致；仅改前置增益保留长尾；静音另一声道保持精确零。
- 同采样率、EQ 旁路的 24 位 FLAC → 最终播放器 Float32 PCM 与解码样本一致。
- 四音固定参数夹具：Float64 残差约 `−261 dBFS`，最终 Float32 约 `−187 dBFS`。这是特定输入和电平的残差，不是所有音乐/电平的噪声上界，更不是模拟耳机口 THD+N。

## 播放链路结论

0.2.0 已通过 [Xcode 26.2 云端构建与 9 项原生测试](https://github.com/windbullet/windblower/actions/runs/42463853824)，含播放中 EQ 校准和 RemoteIO 实际输出，未签名 IPA 已生成。完整验证状态及安装包哈希见 [VALIDATION.md](VALIDATION.md)。

`原文件 → 原采样率解码 → 必要时一次 soxr VHQ → Float64 EQ/单位增益旁路 → Float32 → RemoteIO → 系统 → DAC/耳放/耳机`

不改写原音乐，不默认加入归一化、空间音效、交叉淡化、模拟染色、抖动或响度处理；音量控件使用系统音量。16/24 位整数可精确表示于 Float32，32 位 PCM 到输出接口有舍入；MP3 已有有损编码且内部解码精度受 mpg123 构建限制。

这是一条可说明、可测试、尽量少转换的 App 内链路。iPadOS 的非混音/measurement 模式和 RemoteIO 不提供桌面式独占保证；44.1/48 kHz 等实际路由、耳机口内部 SRC 与模拟性能仍要在 mini 5 上确认。此版本依旧是需要真机验收的测试版本，不能标为整条链路 bit-perfect 或绝对无失真。

参考：[RBJ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)、[TPT SVF](https://cytomic.com/files/dsp/SvfLinearTrapOptimised2.pdf)、[Apple 采样率偏好](https://developer.apple.com/library/archive/qa/qa1631/_index.html)。
