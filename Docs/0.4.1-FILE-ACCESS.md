# 0.4.1：本机文件定位与 FLAC 打开诊断

## 报告与定位范围

用户报告通过 Wi-Fi 上传的多首 FLAC 在 0.4.0 覆盖安装后无法播放；旧版可播放，iPad“文件”中原文件仍在且大小正常，重新扫描 Music 完成后播放仍报错。截图错误为 `Unable to open mono/stereo FLAC`，RemoteIO 客户端显示“尚未校验”。这个错误由解码器打开阶段产生，不能从中判断是文件路径、访问权限、元数据还是声道问题，也不能归因于 EQ、削波或 48 kHz 输出。

本机曲库 320 个 FLAC 的文件头均可由同一内核打开；本机《栞》为 96 kHz / 24 bit / 双声道，共 25,575,680 帧，完整解码与 STREAMINFO MD5 一致。这只验证电脑上的样本，不等于已验证 iPad 上那一份文件或已复现覆盖更新故障。

代码检查发现旧版根据根目录字符串长度截取相对路径，没有先核对路径前缀。对于 `/var`、`/private/var` 或其他指向同一目录的别名，这种做法会产生错误相对路径。0.4.1 修复该确定存在的路径处理缺陷，并补充足以在真机继续定位的诊断；用户本次故障是否正由此触发，仍待真机结果确认。

## 修改

- 导入文件夹及扫描曲库统一解析目录别名，再按路径组件计算相对路径；验证文件确实位于目标目录内，保留中文、日文及文件名中的字面 `%`、`#`。
- 播放、预读下一首与完整峰值分析使用数据库内当前路径，避免继续使用恢复队列里的旧路径。
- 路径失效时，只在 Music 内寻找同文件名或被截短文件名的候选，并验证完整原文件 SHA-256 后修复索引。仅同名而内容不同的文件不会被绑定；没有找到原文件则明确报错。
- 原文件哈希仅在路径失效时按需计算；正常起播只做小量文件头读取，不增加整曲测峰或全库哈希等待。
- FLAC 初始化错误保留 libFLAC 状态与文件系统 errno；元数据不完整和不支持的声道分别报告。播放链路新增本机相对路径、字节数、读取到的前 16 字节及持久到诊断界面的错误文字，导出包含 App 版本与 build。
- 不改动文件内容、解码 PCM、EQ 系数、SRC 或防削波增益算法；不通过转码规避问题。

## 验证

本地 C++ 核心、FLAC/MP3/SRC/连续播放集成及 A/B/超满刻度回归已通过。生成的 Unicode 文件名 FLAC 解码与参考 PCM 逐样本相同，缺失文件、截断元数据和六声道文件分别返回预期类别的错误。

新增原生测试覆盖目录别名/Unicode 相对路径、哈希拒绝同名错误内容、修复失效路径并经 RemoteIO 起播，以及缺失文件诊断。另将生成的 FLAC 经 Wi-Fi 服务分块上传至带日文/%/# 的目录，校验入库、起播、重建曲库与控制器后的队列恢复及再次播放。该重建测试模拟持久化读取，不能替代 Sideloadly 在真机上的覆盖安装验收。云端最终结果和安装包以 [验证状态](VALIDATION.md) 为准。

## 覆盖安装与反馈

沿用原 Apple 账号、应用标识覆盖安装，不先卸载。播放已有歌曲时会按需定位和修复路径，无需先重新传入音乐。

如果仍报错，在“播放链路”查看“本机原文件”和“上次播放错误”，或使用“导出播放链路诊断”。诊断可区分 `errno=2`（找不到文件）、`errno=13`（访问被拒绝）及文件头/声道错误，不再只显示通用英文提示。文件大小相同不能证明原文件哈希相同，诊断也不据此宣称文件完整。
